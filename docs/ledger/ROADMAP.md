# ROADMAP

Order is fixed. A phase starts only when `node tools/gate.mjs --phase <previous>` passes. Row counts come from `node tools/ledger.mjs status --phase Pxx`.

| Phase | Title | Depends on | Goal |
|---|---|---|---|
| P00 | Bootstrap, toolchain and repository | none | Prove the machine can build this project, verify the blueprint, create the repository skeleton exactly as PROJECT-TREE.md says, and make the gate pass on an empty project. |
| P01 | Design system and application shell | P00 | Create the Flutter app and everything every later screen depends on: tokens, themes, fonts, icons, brand, adaptive layout, device tiers, localisation, bidirectional typography, logging, and all 32 components with a debug gallery and golden tests. |
| P02 | Rust cryptographic core and Dart bindings | P00 | Build the vetted-primitive crypto core exactly as specified by Prompt B (blueprint lines 2705-2858): identity, prekeys, hybrid key agreement, Double Ratchet, safety numbers, padding, backup and vault key derivation helpers, recovery phrase, streaming AEAD, FFI. No invented primitives, ever. |
| P03 | Gateway foundation: accounts, keys, messages, queues | P02 | Build the Rust gateway core with a real Postgres, Redis and object store running in docker compose: one-time codes, accounts, tokens, usernames, key bundles, registration lock, message relay over WebSocket with durable per-device queues. |
| P04 | Gateway services: media, push, devices, links, reports, abuse | P03 | Finish the server side that later phases rely on: encrypted media storage, push wake-ups, device linking and approval, contact links, burner usernames, reports and appeals, account deletion, abuse controls. Every endpoint has real integration tests. |
| P05 | Mobile data layer, transport, outbox and settings engine | P02 P03 | Give the app a real encrypted database, real key custody, a real transport and outbox, and a settings engine generated from settings.csv so none of the 214 settings can be missed. |
| P06 | Accounts, onboarding, app lock, devices | P04 P05 | First user-facing slice: sign-up, username, age gate, Secure setup (app lock and recovery key), invites, linked devices, new-device approval, remote wipe, profile, passkeys, registration lock, account deletion. Real server, real keys. |
| P07A | Chat core: 1-on-1 messaging, personas, organisation basics | P06 | The real chat: encrypted 1-on-1 messages end to end, replies, reactions, mentions, edit, delete, undo send, drafts, receipts, typing, link previews, offline queue view, search, folders, pins, mute, archive, Saved Messages. |
| P07B | Message rules, advanced messaging and organisation | P07A | Message Rules with honest labels, Whisper Send, and the advanced messaging and organisation rows. |
| P07C | Privacy controls and basic safety | P07B | Privacy and safety basics: disappearing timers, visibility controls, screenshot blocking, clipboard guard, privacy blur, requests inbox, report, block, appeals, child-safety page, Trust screen and safety numbers. |
| P08 | Media, files and voice | P07C | Photos, video, documents up to 2 GB, voice notes, view-once, EXIF stripping, resumable uploads, galleries, scanner, editor, trimming, location, GIFs, stickers, video notes, smart formats. |
| P09 | Notifications, alerts, Hush mode, focus | P08 | The full notification pipeline and the alert system: content-free push, local notification building, the 8-rule engine in the exact order, channels, Hush mode, health check, alert cards and sheets, focus profiles, prayer times, driving mode, live progress. |
| P10 | Vault core: format, keys, lock model, viewers, leak harness | P09 P02 | Make the two Vault promises true and testable: nothing leaves the Vault to the gallery, other apps, the system or any backup. Implement exactly Prompt C (blueprint lines 2860-2950) for the Vault half. |
| P11 | Vault advanced: decoy, duress, disguise, notes, IDs, checkup, footprint | P10 | Complete the Vault: notes, private contacts, ID wallet, decoy and duress, disguise, intruder log, send-from-Vault, storage manager, checkup, footprint scan, and the bulk move-to-Vault action. |
| P12 | Backup engine (no registry rows; the rows complete in P13) | P10 P02 | Build the backup engine: recovery key, chunker, manifests, encryption, deduplication, retention, garbage collection, destinations, scheduling, verification, restore planner and journal, drills. Exactly Prompt C milestones C8 to C10. |
| P13 | Backup, restore, export and import UI; migrations | P12 | All backup rows with their real UI, the restore wizard, exports, WhatsApp and Telegram import, phone-to-phone transfer, smart storage, forecast. |
| P14A | Groups: MLS groups, roles, admin tools | P13 | Real group chat with OpenMLS: groups up to 100 (then 1,000), roles, topics, links, approvals, slow mode, announcement mode, join questions, admin log, events, polls, history for new members, mentions, member labels, ban list and timed mute. |
| P14B | Communities, channels, group admin automation, Moments | P14A | Communities, broadcast channels, captcha and welcome, auto-moderation on admin devices (with honest labels), ownership succession, templates, and Moments. |
| P15 | Calls | P14B | Real end-to-end encrypted voice and video calls (1-on-1 and group up to 8), native call integration, handover, call links, lobby, hold and waiting, missed-call messages, scheduling, screening, effects, captions hook. |
| P16 | Presenting and screen sharing | P15 | Source-aware presenting: entire screen, one app, files and photos, camera, whiteboard, audio only, with presenter privacy, quality modes, audience controls, recording to the Vault. |
| P17 | On-device AI layer | P08 P11 | Build the on-device AI layer and all 36 AI features, evaluation harness first, with honest capability gating and per-space indexes. |
| P18 | Settings completion, appearance, accessibility, lockdown, Simple mode | P17 | Finish all settings UI: Settings home, 14 group pages, search, presets, overrides, security centre, appearance studio, accessibility suite, Lockdown, Simple mode, wellbeing, tours, shortcuts, tiles and widgets, local automation. |
| P19 | Network resilience, data usage, operations, growth | P18 | Connection fallbacks, outage mode, proxy links, data monitor, update channel, admin tooling, feature flags, analytics opt-in, transparency, help centre, landing page, switch kit, group-move tracker. |
| P20 | Trust and safety extensions | P19 | Sealed sender, message franking, look-alike warnings, link warnings, check-in timer, SOS, help directory, restrict, QR safety scanner, Pakistan scam intelligence in the chat flow. |
| P21 | Version 2 rows: build what is self-contained, document the rest honestly | P20 | Handle the 38 rows the blueprint marks v2. Build the ones that need no outside partner, licence or second client, and give the others a design note, an interface and an honest ledger status. |
| P22 | Hardening, quality gates, compliance | P21 | Prove it: risk register verification, performance and battery budgets, accessibility audit, goldens at five widths, adaptive pass for tablets and desktops, supply-chain checks, docs for auditors, store compliance checklists. |
| P23 | Release candidate and handover | P22 | Final audit and honest handover. Nothing new is built; everything claimed is re-verified. |

Engine-first ordering: a screen is built in the phase that builds its engine, so nothing is ever wired to a fake. This deliberately overrides Blueprint Prompt A (section 19.1), which allowed fake engines; the project rule "no fake implementations" wins (see DECISIONS.md D-01).
